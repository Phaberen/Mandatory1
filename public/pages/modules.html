Modules

CommonJS vs ES Modules

Modules let files share code. CommonJS is the old way with require and module.exports.
ES Modules is the new way with import and export, and needs "type": "module" in package.json.

For example, the bottom snippet is an import example from the code used to make this node.js Docs. ./util/templatingEngine.js. 

// CommonJS
const express = require("express");
module.exports = { readPage };
// ES Modules ("type": "module" in package.json)
import express from "express";
export function readPage(path) { ... }

import { readPage, constructPage } from "./util/templatingEngine.js";

Serving static files

express.static("public") makes every file in the public folder reachable from the browser.
Important to note that the path is now based on /public, so it has to be omitted as shown in 2nd snippet 

app.use(express.static("public"));
public/assets/css/main.css   →   /assets/css/main.css

Environment variables

Environment variables are settings we give the app when we start it, and we read them with process.env. If PORT is not set, we use 8080.

?? only uses 8080 if the value is null or undefined. || also uses it if the value is 0 or empty, which can give the wrong result.

in other words, using || will deem the statement false(falsey) with values like 0 or "" (empty string) 

const PORT = process.env.PORT ?? 8080;
$env:PORT=3000; npm start

0 ?? 8080   // 0
0 || 8080   // 8080
