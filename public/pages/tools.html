Node Package Manager (npm)

npm is a Command Line Interface tool (CLI) installed alongside Node.
It installs, updates and removes packages and runs scripts

npm init creates package.json in the selected folder.
the -y flag accepts all default answers during init so you dont have to

npm i installs everything listed in package.json
if followed by a name, for example express, npm downloads express into node_modules and writes it¨ into package.json 

npm init -y
npm i
npm i express

package.json

A similar to above except this installs and writes the nodemon dependency with a -D flag
this installs nodemon in node_modules, writes it in package.json under devDependencies.

"type": "module" lets node handle the .js files as ES Modules, which lets us import/export rather than require with CommonJS

the dependencies each have a version range.
this means they are compatible with version from current and up, until the next major version change. 

npm i -D nodemon
{
  "type": "module",
  "dependencies": {
    "express": "^5.3.0"
  },
  "devDependencies": {
    "nodemon": "^3.1.14"
  }
}

Scripts

scripts are also placed in package.json.
aside from start, test which are built-in shorthand commands that npm already knows,
scripts are shortcuts for commands. instead of nodemon -e js,json,html app.js we can have a script "dev" that runs by typing npm run dev

it is important to have standards for dev and prod environments. scripts can help with this. 

"scripts": {
  "start": "node app.js",
  "dev": "nodemon -e js,json,html app.js",
  "lint": "eslint .",
  "format": "prettier --write ."
}
npm start
npm run dev

nodemon

Nodemon is a program that watches for file changes, and it exits + restarts the app when they occur.
great for development as you almost instantly view changes to the running app.

"dev": "nodemon -e js,json,html app.js" replaces the list of files nodemon watches, with the one provided.
this was done to have nodemon restart app upon html changes as well as .js file changes. 

npm run dev
[nodemon] watching extensions: js,json,html
[nodemon] starting `node app.js`
[nodemon] restarting due to changes...

ESLint and Prettier

Eslint is considerd the "de facto standard" linter for js.
Linters read code without running it. they finds bugs, errors, unused variables etc. in your code.
they enforce good code conventions by setting standards everyone follows.

prettier is used for formatting, for example: trailing spaces, unconventional/wrong indentations. it generally provides format symmetry everywhere in your code

here we again download to node_modules, write it in package.json under devDependencies
lint, format are scripts defined in package.json 

npm init @eslint/config@latest
npm i -D prettier
npm run lint
npm run format

git

in.gitignore node_modules because we don't want it pushed to github repository.
is is quite large and clutters the remote repository with sizey files
most importantly, it is reproducible from our package-lock.json that holds our exact dependencies and their versions.
therefore anyone pulling the repository can recreate the exact node_modulesdirectory.

simple git:
1. initializes git in directory
2. add "." means add all file changes in current working directory and all of subdirectories.
3. commits the added changes to git, with a message.
4. pushes the unpushed commits to the remote repository on github.
